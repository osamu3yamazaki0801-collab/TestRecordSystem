# 試験記録台帳

## 概要
Python製Webサーバーとサーバー側SQLiteを使い、複数利用者で試験結果を共有する台帳です。HTMLファイルを直接開かず、必ずサーバー経由でアクセスしてください。

ログイン後はReactで作成したダッシュボードが表示されます。登録済み件数、今月の登録件数、直近の登録を確認でき、サイドメニューやクイックアクセスから「記録の登録・検索」へ移動できます。新規登録はこの画面に統合しており、独立した「新規登録」メニューはありません。一覧の「コピー」から登録項目を新規登録ダイアログへコピーできます（添付ファイルはコピーされません）。また、記録の変更・削除ができます。変更では既存の添付ファイルを維持したまま項目を編集し、添付を追加したり、選択した添付を削除したりできます。削除前に確認が表示され、削除した記録は復元できません。Python／FlaskとSQLiteはAPIおよびデータ保存に使用します。

開発時はPowerShellを2つ開きます。Python APIサーバーとReactの開発サーバーを起動します。

## 記録の登録・検索
概要画面には「新規登録」ボタンを置かず、「記録の登録・検索」から登録します。

検索条件は試験番号・案件名・製番・登録日・担当者の順に表示します。案件名は30文字以内で、他の条件と同じく前方一致・`*` ワイルドカード検索ができ、複数の条件を組み合わせて絞り込めます。

画面右上の「システム稼働中」の下にある「新規登録」を押すと、試験番号と担当者だけを入力するダイアログが開きます。「登録」で記録を保存し、ダイアログを閉じて一覧に追加した記録を選択します。登録後は検索条件を解除して新しい記録を表示します。通常の新規登録では登録日を当日とし、案件名・製番は空欄で保存します。案件名・製番は任意項目で、詳細画面で後から追記できます。

更新後も新規登録で案件名の必須エラーが表示される場合は、更新前のPython APIサーバーが動いている可能性があります。サーバーのターミナルで `Ctrl+C` を押して停止し、`./start-server.ps1` で再起動してください。パスワードはターミナルへ直接入力し、その後ブラウザーを再読み込みしてください。

## 記録の詳細とジャンパ確認
「記録の登録・検索」の一覧で行をクリックすると、選択した行の色が変わります。行をダブルクリックするか「詳細」を押すと、別のブラウザータブで詳細画面が開きます。キーボードでは行にフォーカスしてスペースで選択、Enterで別タブに詳細を開けます。検索一覧を残したまま複数件の詳細を開き、各タブで独立して編集・保存できます。タブ名には試験番号を表示します。一覧の「変更」ボタンは廃止し、詳細画面で試験番号・案件名・製番・登録日・担当者・試験結果を編集します。

詳細URLは `/?recordId=<記録ID>` です。再読み込みやURLからの再表示に対応し、未ログインの場合はログイン後に対象記録を開きます。一覧タブに戻ると、検索条件を維持して結果を更新します。同じ記録を複数タブで編集した場合は最後の保存が優先されるため、同じ記録の同時編集には注意してください。

試験結果ファイルの追加・削除・ダウンロードは詳細画面で行います。検索一覧には添付ファイルを表示せず、新規登録にはファイル選択欄を設けません。まず記録を登録し、検索から詳細画面を開いてファイルを追加してください。

詳細画面の最下部にある共通の「変更を保存」で、登録項目・添付ファイル・機器情報・ジャンパ確認をまとめて保存します。すべての入力を検証し、SQLiteの1つのトランザクションで更新するため、一部だけ保存されることはありません。既存の添付ファイルは維持され、新しい添付の追加や「削除する」で選択した添付の削除ができます。「変更をキャンセル」で全項目の未保存変更と添付選択を破棄して保存済みの内容に戻します。未保存の変更がある場合は破棄の確認が表示されます。

ジャンパ設定は全記録共通で `W1: 1-2`、`W2: 1-2` です。機器情報の下、詳細画面の最後の入力項目として表示します。結果欄の四角をクリックするとチェックに変わり、もう一度クリックすると未確認に戻ります。クリック時には保存せず、共通の「変更を保存」で確認結果を確定します。保存失敗時は入力内容を維持し、エラーを表示します。確認結果は記録ごとにSQLiteへ保存され、再起動後や他のログイン済み利用者にも共有されます。詳細タブは右上の閉じるボタンまたはEscで閉じます。ブラウザーがタブを閉じる操作を制限する場合は、ブラウザーのタブ操作で閉じてください。

詳細画面は登録項目・添付ファイルの下に、次の機器情報を表示し、その後にジャンパ設定を配置します。

- 基板番号：基板名7件は固定です。レビジョン・ネガは半角英数字5文字以内、シリアル No.は100文字以内で入力します。
- 使用計測器：5行の計測器名・管理番号は任意文字列を入力できます。候補と自動入力する管理番号はルートの `equipment-config.json` で設定します。
- インストールソフト・PLDバージョン：ソフト名とSD形式3件は固定、バージョン・チェックサムは空欄から入力します。

各入力欄は100文字以内です。「機器情報を保存」ボタンは廃止し、共通の「変更を保存」で保存します。記録項目・添付・機器情報・ジャンパ確認に未保存の変更がある場合、タブを閉じる・再読み込み・画面離脱時にブラウザー標準の警告が表示されます。

計測器の候補は、ルートの `equipment-config.json` にある `instrumentChoices` 配列で設定します。各項目に `name` と `managementNo` を指定してください。変更後はPython APIサーバーを再起動してください。別のJSONファイルを使う場合は `LEDGER_EQUIPMENT_CONFIG_PATH` にパスを設定します。

更新後はPython APIサーバーを再起動してください。共通保存API `PUT /api/records/<記録ID>/details` は更新後のサーバーで利用できます。確認結果と機器情報のテーブルは起動時に自動作成されます。FlaskからReact画面を配信する場合は `npm run build` も必要です。

## 試験結果CSV
詳細画面から新しく追加する試験結果ファイルはCSV形式（`.csv`）とし、UTF-8（BOMあり・なし）またはShift_JIS（CP932）に対応します。1件100 MB以下、1回に追加する合計100 MB以下の制限は従来どおりです。

CSVの先頭に「品名」「仕様書番号」「試験番号」の2列の基本情報を記載し、その下に「試験結果 1」「試験結果 2」の見出し・温度行・項目行・明細を配置します。試験結果1は下限値・上限値・単位と3温度のMIN／判定／MAX／判定、試験結果2は規定値・単位と3温度の測定値／判定を表示します。

「試験結果（CSV）」には基本情報と温度別の表を表示し、結果の種類をタブで切り替えます。PASSは緑、FAILは赤、空欄の判定は「-」で表示します。FAILを含む試験項目は行全体を強調し、PASS・FAIL・未判定の項目数を集計します。試験項目名・No.の検索、判定による絞り込み、50件ずつのページ送りができます。幅の広い表は表の内側でスクロールします。HEXの先頭ゼロや測定値の桁は変換しません。

新しく選択したCSVは保存前プレビューで表示し、複数のCSVがある場合はファイルを切り替えられます。プレビューでは台帳を変更せず、共通の「変更を保存」で形式を検証して保存します。不正なCSVはエラーを表示し、記録や他の項目も保存しません。既存のCSV以外の添付は削除せず、従来どおりダウンロードできますが、結果表としては表示しません。

CSV表示・プレビューAPIを追加したため、更新後はPython APIサーバーを再起動してください。CSV内の基本情報は表示のみとし、台帳の試験番号などを自動で上書きしません。

## サーバ側開発環境のインストール
Python 3.10以上を用意し、試験台帳フォルダーで次を実行します。

```powershell
py -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
```

### サーバ側の起動
#### 本番
本番では、次の環境変数をサーバーのサービスアカウントに設定します。値をソースコードや共有リポジトリに書かないでください。

- `LEDGER_SECRET_KEY`: 推測困難なランダム文字列（例: `py -c "import secrets; print(secrets.token_urlsafe(48))"` で生成）
- `LEDGER_USERNAME`: 台帳のログインID
- `LEDGER_PASSWORD_HASH`: 以下のコマンドで生成したパスワードハッシュ
- `LEDGER_DATABASE_PATH`: SQLiteファイルの絶対パス（省略時は `instance\trial-ledger.sqlite3`）
- `LEDGER_HOST`: 待受アドレス（既定 `127.0.0.1`。リバースプロキシを使わず社内LANに公開する場合はサーバーの運用設定に合わせて指定）
- `LEDGER_PORT`: 待受ポート（既定 `8000`）
- `LEDGER_COOKIE_SECURE`: HTTPS運用では既定値の `1` を使用。ローカルHTTP開発時のみ `0` にする

パスワードハッシュを対話入力で生成します。

```powershell
.\.venv\Scripts\python -c "from getpass import getpass; from werkzeug.security import generate_password_hash; print(generate_password_hash(getpass()))"
```

本番では、これらの値をWindowsサービスの実行環境へ登録し、サービスアカウント以外からシークレットとDBファイルを読めないようACLを設定します。`LEDGER_SECRET_KEY` とパスワードハッシュをソース管理や一般ユーザーから読める設定ファイルに保存しないでください。ローカルで動作を確認するときは、PowerShellの同じウィンドウ内で環境変数を設定して起動できます。

#### ローカルで動作確認するとき
`TestRecordSystem` フォルダーで、次のスクリプトを実行します。仮想環境のPythonを使用するため、事前のactivateは不要です。

```powershell
.\start-server.ps1
```

ログインIDは `toshiba` です。起動時に `Password:` と表示されたら、ログインに使うパスワードを入力します（入力内容は表示されません）。パスワードはファイルに保存せず、起動するたびに入力します。サーバーの停止は `Ctrl+C` です。このスクリプトは `LEDGER_COOKIE_SECURE=0` を設定するため、ローカルHTTP開発専用です。

ログインIDを変更する場合は `.\start-server.ps1 -Username "別のID"` を実行します。実行ポリシーでブロックされる場合は、組織のポリシーで許可されている範囲で `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-server.ps1` を使用できます（このプロセスのみ対象で、永続的な設定変更はしません）。

## React開発環境
### 開発環境のインストール
Node.js LTSとnpmをインストールします（Windowsの例）。最初だけ
```powershell
winget install --id OpenJS.NodeJS.LTS --exact
```

### プロジェクトの作成インストール
```powershell
npm create vite@latest my-react-app -- --template react-ts
Set-Location my-react-app
npm install
```


## Reactの開発サーバ起動
```powershell
Set-Location frontend
npm run dev
```

ブラウザーではViteが表示する `http://127.0.0.1:5173/` を開きます。API通信は開発サーバーから `http://127.0.0.1:8000/` のFlaskへ転送されます。

本番用ファイルは次のコマンドで `frontend\dist` に生成します。Flaskはこのビルド済みReact画面を `/` で配信します。ビルド後は従来どおり `http://127.0.0.1:8000/`（本番環境ではHTTPSの社内URL）を開きます。


## ビルド
```powershell
Set-Location frontend
npm run build
```
FlaskはReactビルドが見つからないときに旧HTML画面へ切り替えず、`npm run build` が必要であることをエラーで知らせます。

HTTPSを提供する社内リバースプロキシの背後で運用し、利用者は `https://<社内ホスト>/` にアクセスします。TLS証明書、ファイアウォール、サービス自動起動、アクセス可能な利用者の範囲はサーバー管理者が設定してください。本番では `LEDGER_COOKIE_SECURE=0` にしないでください。

## 保存と制限
- 試験データと添付ファイルはサーバー上のSQLiteに保存され、ブラウザーごとに分離されません。
- 1つの記録に複数の添付ファイルを登録できます。追加する添付ファイルは1件100 MB以下、1回の登録・変更で選択する合計も100 MB以下です。リバースプロキシ経由で公開する場合は、プロキシのリクエスト本文サイズ上限を102 MiBより大きく設定してください。ファイルはログイン済み利用者だけがダウンロードできます。
- ログインは環境変数で設定するアプリ専用アカウントです。パスワードはハッシュとして保存します。利用者別の権限管理や社内SSOが必要な場合は、その認証基盤との連携が別途必要です。
- `LEDGER_DATABASE_PATH` のSQLiteファイルと同じ場所に作られる `-wal` / `-shm` ファイルも含めて保護してください。実行中のSQLiteファイルを単純コピーせず、SQLiteのバックアップ機能または停止後のバックアップを使い、復元手順も定期的に確認してください。
- ブラウザーのlocalStorageに以前登録したデータはサーバーへ自動移行されません。必要な記録は別途移行してください。
- この構成は単一サーバー向けです。複数サーバー構成や大規模な同時書き込みにはSQLiteを共有せず、PostgreSQL等へ移行してください。
