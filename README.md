# 試験記録台帳

## 概要
Python製Webサーバーとサーバー側SQLiteを使い、複数利用者で試験結果を共有する台帳です。HTMLファイルを直接開かず、必ずサーバー経由でアクセスしてください。

ログイン後はReactで作成した概要画面が表示され、登録済み総件数、今月の登録件数、当年の担当者別対応件数・対応比率を確認できます。「記録の登録」と「記録の検索」へのボタンは概要画面に横並びで配置しています。サイドメニューから登録画面と検索画面を切り替えます。一覧の「コピー」から登録項目を記録の登録画面へコピーできます（添付ファイルや機器情報はコピーされません）。検索一覧から記録の詳細を別タブで開いて変更し、または記録を削除できます。変更では既存CSVを維持したまま項目を編集し、CSVを追加・削除できます。削除前に確認が表示され、削除した記録は復元できません。詳細は[要件定義書](docs/試験結果台帳要件.md)を参照してください。Python／FlaskとSQLiteはAPIおよびデータ保存に使用します。

開発時はPowerShellを2つ開きます。Python APIサーバーとReactの開発サーバーを起動します。

## 記録の登録
サイドメニューの「記録の登録」を選ぶと、試験記録の登録画面が表示されます。試験番号・案件名・製番・登録日・担当者を入力します。試験番号・担当者・登録日は必須で、登録日は本日の日付が初期値として入力されています。担当者は管理者のユーザー管理画面で作成した有効な担当者アカウントから選択します。案件名・製番は任意項目です。

記録の登録画面を開くと、サーバーの日付を基準に `YY0NNNNN` 形式の試験番号が自動入力されます（西暦下二桁 + 試験器番号 `0` + 5桁の通し番号）。例：2026年は `26000000`、次は `26000001` です。年が変わると通し番号は `00000` から始まり、登録済み番号と同じ画面内の入力番号を除いた最小の空き番号を使用します。未登録の番号は予約済みとして消費せず、次回表示時にも空き番号を使用します。手入力を含め、既に登録されている試験番号と重複する番号は登録できず、重複メッセージが表示されます。複数行登録でも、入力行同士の重複があれば全件を登録しません。

「記録を追加」で入力行を増やし、複数件をまとめて登録できます。追加行には案件名・登録日・担当者の値が引き継がれ、試験番号は自動で入力されるため、必要に応じて変更してください。入力行のいずれかに誤りがある場合は全件を登録しません。保存が完了すると入力欄がクリアされ、記録の検索画面へ移動して登録した記録を一覧に表示します。
試験結果CSVを選択すると、そのCSVに含まれる「品名」を案件名へ、「仕様書番号」を製番へ自動転記します。CSVの内容を変更した場合は、転記後の案件名・製番を必要に応じて確認・修正できます。

## 記録の検索
サイドメニューの「記録の検索」を選ぶと、登録済み記録の検索画面が表示されます。検索条件は試験番号・案件名・製番・登録日・担当者の順に表示します。案件名は30文字以内で、他の条件と同じく前方一致・`*` ワイルドカード検索ができ、複数の条件を組み合わせて絞り込めます。

更新後も新規登録で案件名の必須エラーが表示される場合は、更新前のPython APIサーバーが動いている可能性があります。サーバーのターミナルで `Ctrl+C` を押して停止し、`./start-server.ps1` で再起動してください。パスワードはターミナルへ直接入力し、その後ブラウザーを再読み込みしてください。

## 記録の詳細とジャンパ確認
詳細画面は「試験情報」「受入検査」「試験結果」「出荷検査」「回覧」の5タブです。「出荷検査」は「試験結果」の右隣にあり、「出荷用ソフトインストール」の表を1行表示します。ソフト・SD形式・バージョン・チェックサムの4列はすべて自由入力で、初期値は空欄です。各項目は任意入力で100文字以内とし、共通の「保存」で保存、「キャンセル」で未保存の変更を破棄できます。受入検査のソフト情報とは独立して保存され、`equipment-config.json` では設定しません。既存の出荷用ソフトの保存値は引き継ぎ、受入検査の入力値も変わりません。更新後はPython APIサーバーを再起動してください。Flaskから画面を配信する場合はReactの再ビルドも必要です。

出荷用ソフトの「試験時と同じソフト」をチェックすると、入力内容を保持したまま4列を編集不可にし、セルを灰色で表示します。チェックを外すと再び編集できます。受入検査からの自動コピーは行いません。チェック状態も共通の「保存」「キャンセル」の対象で、記録ごとに保存されます。既存記録を含め、未保存時の初期状態はチェックなしです。

「記録の検索」画面の一覧で行をクリックすると、選択した行の色が変わります。行をダブルクリックするか「詳細」を押すと、別のブラウザータブで詳細画面が開きます。キーボードでは行にフォーカスしてスペースで選択、Enterで別タブに詳細を開けます。検索一覧を残したまま複数件の詳細を開き、各タブで独立して編集・保存できます。タブ名には試験番号を表示します。一覧の「変更」ボタンは廃止し、詳細画面で試験番号・案件名・製番・登録日・担当者・試験結果を編集します。

詳細URLは `/?recordId=<記録ID>` です。再読み込みやURLからの再表示に対応し、未ログインの場合はログイン後に対象記録を開きます。一覧タブに戻ると、検索条件を維持して結果を更新します。同じ記録を複数タブで編集した場合は最後の保存が優先されるため、同じ記録の同時編集には注意してください。

未保存変更のある詳細画面で、ブラウザーの閉じる操作の警告をキャンセルした場合は、入力を維持して保存を続けられます。旧形式の機器情報に残っている内部管理項目は読み込み時に取り除き、ソフト名・SD形式・バージョン・チェックサムなどの入力値は維持します。更新後はPython APIサーバーを再起動し、詳細画面を開き直してください。

新規登録時に各記録の行へ試験結果CSVを添付できます。検索一覧には添付ファイルを表示せず、詳細画面からは試験結果ファイルの追加・削除・ダウンロードを行えます。

詳細画面の最下部にある共通の「変更を保存」で、登録項目・添付ファイル・機器情報・ジャンパ確認をまとめて保存します。すべての入力を検証し、SQLiteの1つのトランザクションで更新するため、一部だけ保存されることはありません。既存の添付ファイルは維持され、新しい添付の追加や「削除する」で選択した添付の削除ができます。「変更をキャンセル」で全項目の未保存変更と添付選択を破棄して保存済みの内容に戻します。未保存の変更がある場合は破棄の確認が表示されます。

ジャンパ設定はルートの `equipment-config.json` にある `jumpers` 配列で名前・設定・表示行数を指定します。「受入検査」タブの外観確認の下、インストールソフトの上に表示します。結果欄の四角をクリックするとチェックに変わり、もう一度クリックすると未確認に戻ります。クリック時には保存せず、共通の「変更を保存」で確認結果を確定します。保存失敗時は入力内容を維持し、エラーを表示します。確認結果は記録ごとにSQLiteへ保存され、再起動後や他のログイン済み利用者にも共有されます。詳細タブは右上の閉じるボタンまたはEscで閉じます。ブラウザーがタブを閉じる操作を制限する場合は、ブラウザーのタブ操作で閉じてください。

## アプリ内回覧とユーザー管理

初回起動時に `LEDGER_USERNAME` と `LEDGER_PASSWORD_HASH` を設定すると、そのIDが初期管理者になります。開発用の `.\start-server.ps1` は、ユーザーテーブルが空の初回だけパスワードを尋ねます。初期管理者でログイン後、サイドメニューの「ユーザー管理」から担当者ごとのアカウントを作成してください。ログインIDは3～50文字の半角英数字・ピリオド・ハイフン・アンダースコア、パスワードは12文字以上です。パスワードはハッシュ化して保存し、管理者は再設定またはアカウントの無効化ができます。

担当者アカウントは管理者の「ユーザー管理」画面で担当者名、メールアドレス、ログインID、初期パスワードを登録して作成します。アカウントを作成すると、その担当者を記録登録と回覧先の候補として選べるようになります。アカウントを無効化すると候補から除外され、削除すると再作成できるようになります。

記録詳細の「回覧」タブで1～20段階を設定します。初期表示は「担当 → 調査」の2段階で、段階名は「担当」「調査」「承認」から選べます。フローを保存して「回覧を開始」を押すと、最初の担当者の「回覧タスク」に表示されます。担当者が完了すると次の担当者のタスクに切り替わり、最終段階を完了すると回覧が終了します。担当者本人だけが自分の段階を進められます。管理者は全員のタスクを確認し、代理で回覧を進めることもできます。状態と操作履歴は記録ごとに保存されます。

回覧の通知・引き継ぎはアプリ内で行い、メール送信やSMTP設定は使用しません。そのため、担当者はアプリにログインして「回覧タスク」を確認してください。Windowsサービスで運用する場合、初回起動時だけ `LEDGER_USERNAME` と `LEDGER_PASSWORD_HASH` をサービス環境に設定して初期管理者を作成します。アカウント作成後はユーザー情報をSQLiteに保存するため、これらの初期管理者用環境変数はサービス環境から削除できます。

「受入検査」タブの外観確認とジャンパ設定の間に「誤挿入キー確認」の表を表示します。バックボード側の各コネクタについて、表の塗りつぶされた位置にキーがあることを確認し、最下段の確認欄をチェックします。位置は固定表示で、P31はE・F・G・M、P32はE・F・H・L、P34はE・F・L・M、PS3はE・H・K・Lです。右隣の基板側はP31にINF265、P32にPWM85、P34にINF267、PS3にPWS132が対応し、A〜Dはキーなし、E〜M（Jを除く）はバックボード側にキーがない位置にキーを表示します。画面幅が足りない場合は横スクロールできます。確認欄は各側に１つずつあり、その側の全コネクタを確認後にチェックします。以前の記録で一部だけ確認済みの場合は未確認と表示しますが、確認欄を操作しない限り元の結果は維持します。確認欄はクリックまたはスペースキーで切り替え、共通の「保存」で記録ごとに保存します。「キャンセル」で未保存の変更を破棄できます。

「受入検査」タブの先頭には「外観確認」を表示します。表示内容は `equipment-config.json` の `appearanceInspection` で設定します。確認対象の□をクリックするか、Tabキーで選んでスペースキーを押すと、ジャンパ設定と同じチェック済み表示に切り替わります。「-」のセルは対象外です。共通の「保存」で記録ごとに保存し、「キャンセル」で未保存の変更を破棄します。サーバー再起動時に保存用テーブルが自動作成・移行されます。

外観確認の `boardGroups` には見出しの `name` と基板名の配列 `boards` を指定します。複数基板のグループは結合見出しになります。`items` の項目を追加・削除・並べ替えると、その順序で表に反映します（最大50項目、基板列は合計50件）。各項目の `rows` を `1` にすると基準値とチェックを1行に表示し、`2` にすると番号・項目名を縦に結合して、上段に基準値、下段にチェックを表示します。`values` に基板名を指定しなければ対象外、値が `""` なら基準値なしのチェック欄です。`items` を空配列にすると確認項目なしになり、`appearanceInspection` 自体を省略すると従来の6項目を表示します。

たとえば `appearanceInspection.items` 配列に次の項目を追加できます。

```json
[
  { "key": "seal", "name": "封印確認", "rows": 1, "values": { "PWS132": "" } },
  { "key": "label", "name": "ラベル確認", "rows": 2, "values": { "PWS132": "LABEL-1", "PWM85": "LABEL-2" } }
]
```

`key` は英字で始まる半角英数字・`_`・`-` の50文字以内で、一意にしてください。名前・基準値は各100文字以内です。`key` は保存結果の識別に使うため、並べ替えや表示行数の変更では維持してください。項目名や基準値を変更したセルは未確認になります。設定変更後はサーバーを再起動し、ブラウザーを再読み込みしてください。

詳細画面の「試験情報」と「受入検査」タブに、次の機器情報とジャンパ設定を表示します。

- 基板情報：表示行数と既定値はルートの `equipment-config.json` にある `boards` 配列で設定します。基板名とシリアル No.を表示し、シリアル No.は100文字以内で入力します。
- 使用計測器：5行の計測器名・管理番号は任意文字列を入力できます。候補と自動入力する管理番号はルートの `equipment-config.json` で設定します。
- ジャンパ設定：表示する行数と「ジャンパ名」「設定」は `jumpers` 配列で設定します。各要素は `{"name": "W1", "setting": "1-2"}` の形式で、重複しない名前を最大50件指定できます。配列を空にすると行は表示されません。未指定の場合は従来どおりW1・W2を表示します。
- インストールソフト／PLDバージョン：区分・表示行・ソフト名・SD形式は `equipment-config.json` の `softwareSections` で設定し、バージョン・チェックサムを入力します。

各入力欄は100文字以内です。「機器情報を保存」ボタンは廃止し、共通の「変更を保存」で保存します。記録項目・添付・機器情報・ジャンパ確認に未保存の変更がある場合、タブを閉じる・再読み込み・画面離脱時にブラウザー標準の警告が表示されます。

担当者名とメールアドレスは `equipment-config.json` ではなく、管理者の「ユーザー管理」画面で管理します。担当者名は重複しない日本語と半角数字で30文字以内にしてください。計測器の候補は `instrumentChoices` 配列で設定し、各項目に `name` と `managementNo` を指定してください。基板の表示行数と既定値は `boards` 配列の要素数と内容で設定します（最大50件）。各要素に `name`、`serialNumber` を指定します（各100文字以内）。レビジョン・ネガは設定・表示・入力の対象外です。既存記録のシリアル番号は維持されます。ジャンパ設定は `jumpers` 配列に各要素の `name`・`setting` を設定します（最大50件、名前・設定は各100文字以内、名前は重複不可）。ジャンパ設定を表示しない場合は空配列を指定できます。空欄の既定値は `""` にしてください。変更後はPython APIサーバーを再起動してください。別のJSONファイルを使う場合は `LEDGER_EQUIPMENT_CONFIG_PATH` にパスを設定します。

`softwareSections` では受入検査タブのインストールソフト・PLDバージョン等のセクションを設定します。各セクションに一意な `key`、見出し `title`、`rows` を指定し、各行に固定表示する `name` と `sdFormat` を設定します。最大20セクション・合計50行です。入力済みのバージョン・チェックサムは、同じ `name` と `sdFormat` の行に引き継がれます。

更新後はPython APIサーバーを再起動してください。共通保存API `PUT /api/records/<記録ID>/details` は更新後のサーバーで利用できます。確認結果と機器情報のテーブルは起動時に自動作成されます。FlaskからReact画面を配信する場合は `npm run build` も必要です。

## 試験結果CSV
記録の登録画面では、各記録に試験結果CSVを任意で1件添付できます。複数件を一括登録する場合も各行に個別のCSVを添付でき、保存時に形式を検証します。詳細画面からの追加にも対応します。CSVはUTF-8（BOMあり・なし）またはShift_JIS（CP932）に対応し、1ファイル100 MB以下、1回の登録・追加で合計100 MB以下です。登録した記録の詳細を開くと、CSVから取り込んだ試験結果1・試験結果2などが表示されます。

CSVの先頭に「品名」「仕様書番号」「試験番号」の2列の基本情報を記載し、その下に「試験結果 1」「試験結果 2」の見出し・温度行・項目行・明細を配置します。試験結果1は下限値・上限値・単位と3温度のMIN／判定／MAX／判定、試験結果2は規定値・単位と3温度の測定値／判定を表示します。

「試験結果（CSV）」には基本情報と温度別の表を表示し、結果の種類をタブで切り替えます。PASSは緑、FAIL・NGは赤、空欄の判定は「-」で表示します。FAILまたはNGを含む試験項目は行全体を強調し、PASS・FAIL・未判定の項目数を集計します。試験項目名・No.の検索、判定（NG・未判定・PASS）による絞り込み、50件ずつのページ送りができます。幅の広い表は表の内側でスクロールし、列の境界をドラッグして幅を調整できます。HEXの先頭ゼロや測定値の桁は変換しません。

新しく選択したCSVは保存前プレビューで表示し、複数のCSVがある場合はファイルを切り替えられます。プレビューでは台帳を変更せず、共通の「変更を保存」で形式を検証して保存します。不正なCSVはエラーを表示し、記録や他の項目も保存しません。既存のCSV以外の添付は削除せず、従来どおりダウンロードできますが、結果表としては表示しません。

CSV表示・プレビューAPIを追加したため、更新後はPython APIサーバーを再起動してください。CSV内の基本情報は表示のみとし、台帳の試験番号などを自動で上書きしません。

`equipment-config.json` の `manualTests` には、CSVの上に表示する手動試験を設定します。各試験は `key`、`number`、`name`、`area`、`items` を持ち、測定項目は `key`、`name`、`lowerLimit`、`upperLimit`、`unit`、`benchLock` を持ちます。測定値を入力すると下限値から上限値までの範囲判定で「PASS」または「NG」を表示します。規定値の桁数を固定したい場合は `"49.0"` のように数値文字列で設定できます。空欄は未判定、ペンキロック対象の行はチェックを保存できます。手動試験表の上で入力する温度・湿度も、測定値と確認結果とともに共通の「保存」で記録ごとに保存されます。

## サーバ側開発環境のインストール
Python 3.10以上を用意し、試験台帳フォルダーで次を実行します。

```powershell
py -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
```

### サーバ側の起動
#### 本番
本番では、次の環境変数をサーバーのサービスアカウントに設定します。値をソースコードや共有リポジトリに書かないでください。

- `LEDGER_SECRET_KEY`: 推測困難なランダム文字列（例: `py -c "import secrets; print(secrets.token_urlsafe(48))"` で生成）
- `LEDGER_USERNAME`: 初期管理者のログインID。ユーザーテーブルが空の初回起動時のみ必要
- `LEDGER_PASSWORD_HASH`: 初期管理者のパスワードハッシュ。ユーザーテーブルが空の初回起動時のみ必要
- `LEDGER_DATABASE_PATH`: SQLiteファイルの絶対パス（省略時は `instance\trial-ledger.sqlite3`）
- `LEDGER_BACKUP_PATH`: バックアップ先の絶対パス（省略時は `instance\backups`）
- `LEDGER_BACKUP_INTERVAL_SECONDS`: バックアップ間隔（秒、既定 `86400`）
- `LEDGER_BACKUP_CHECK_INTERVAL_SECONDS`: 稼働中のバックアップ期限確認間隔（秒、既定 `3600`）
- `LEDGER_BACKUP_RETENTION_COUNT`: 保持するバックアップ世代数（既定 `7`）
- `LEDGER_HOST`: 待受アドレス（既定 `127.0.0.1`。リバースプロキシを使わず社内LANに公開する場合はサーバーの運用設定に合わせて指定）
- `LEDGER_PORT`: 待受ポート（既定 `8000`）
- `LEDGER_COOKIE_SECURE`: HTTPS運用では既定値の `1` を使用。ローカルHTTP開発時のみ `0` にする

パスワードハッシュを対話入力で生成します。

```powershell
.\.venv\Scripts\python -c "from getpass import getpass; from werkzeug.security import generate_password_hash; print(generate_password_hash(getpass()))"
```

本番では、これらの値をWindowsサービスの実行環境へ登録し、サービスアカウント以外からシークレットとDBファイルを読めないようACLを設定します。初期管理者の作成後は `LEDGER_USERNAME` と `LEDGER_PASSWORD_HASH` をサービス環境から削除できます。`LEDGER_SECRET_KEY` をソース管理や一般ユーザーから読める設定ファイルに保存しないでください。

#### ローカルで動作確認するとき
`TestRecordSystem` フォルダーで、次のスクリプトを実行します。仮想環境のPythonを使用するため、事前のactivateは不要です。

```powershell
.\start-server.ps1
```

初回起動時だけ `Initial administrator password:` と表示されます。入力したパスワードは初期管理者アカウントとしてSQLiteにハッシュ保存され、画面への入力内容は表示されません。初期管理者IDは既定で `toshiba` です。2回目以降はデータベース内のアカウントでログインし、起動時にパスワードを聞かれることはありません。初期管理者IDを変更する場合は、ユーザーテーブルが空の初回に `.\start-server.ps1 -Username "別のID"` を実行してください。サーバーの停止は `Ctrl+C` です。このスクリプトは `LEDGER_COOKIE_SECURE=0` を設定するため、ローカルHTTP開発専用です。

実行ポリシーでブロックされる場合は、組織のポリシーで許可されている範囲で `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-server.ps1` を使用できます（このプロセスのみ対象で、永続的な設定変更はしません）。

## React開発環境
### 開発環境のインストール
Node.js LTSとnpmをインストールします（Windowsの例）。最初だけ
```powershell
winget install --id OpenJS.NodeJS.LTS --exact
```

### プロジェクトの作成インストール
プロジェクトを作成するときだけ
```powershell
npm create vite@latest my-react-app
Set-Location my-react-app
npm install
```


## Reactの開発サーバ起動
```powershell
Set-Location frontend
npm run dev
```

ブラウザーではViteが表示する `http://127.0.0.1:5173/` を開きます。API通信は開発サーバーから `http://127.0.0.1:8000/` のFlaskへ転送されます。

本番用ファイルは次のコマンドで `frontend\dist` に生成します。Flaskはこのビルド済みReact画面を `/` で配信します。ビルド後は従来どおり `http://127.0.0.1:8000/`（本番環境ではHTTPSの社内URL）を開きます。


## ビルド
```powershell
Set-Location frontend
npm run build
```
FlaskはReactビルドが見つからないときに旧HTML画面へ切り替えず、`npm run build` が必要であることをエラーで知らせます。

HTTPSを提供する社内リバースプロキシの背後で運用し、利用者は `https://<社内ホスト>/` にアクセスします。TLS証明書、ファイアウォール、サービス自動起動、アクセス可能な利用者の範囲はサーバー管理者が設定してください。本番では `LEDGER_COOKIE_SECURE=0` にしないでください。

## 保存と制限
- 試験データと添付ファイルはサーバー上のSQLiteに保存され、ブラウザーごとに分離されません。
- 1つの記録に試験結果CSVを1件登録できます。添付ファイルは1件100 MB以下、1回の登録・変更で追加する合計も100 MB以下です。リバースプロキシ経由で公開する場合は、プロキシのリクエスト本文サイズ上限を102 MiBより大きく設定してください。ファイルはログイン済み利用者だけがダウンロードできます。旧データに複数の添付がある場合は、詳細画面から引き続き参照・ダウンロードできます。
- 初期管理者と担当者アカウントはSQLiteに保存し、パスワードはハッシュ化します。初期管理者のパスワードハッシュとセッション署名鍵を保護し、担当者のアカウントは「ユーザー管理」画面で管理してください。
- 回覧タスクはアプリ内に表示します。メール通知やSMTPは使わず、現在の担当者本人または管理者だけが回覧を進められます。
- アプリ起動時と稼働中、前回のバックアップから24時間以上経過していればSQLiteのオンラインバックアップAPIでDBを複製します。バックアップ先は `LEDGER_BACKUP_PATH`、保持世代数は `LEDGER_BACKUP_RETENTION_COUNT` で設定できます。既定では `instance\backups` に最新7世代を保持します。
- 本番では `LEDGER_BACKUP_PATH` をDBと異なるディスクや共有保存領域に指定してください。バックアップ失敗時はサーバーログに記録し、アプリ本体は継続します。バックアップ後は `PRAGMA integrity_check` で整合性を確認し、復元手順も定期的に確認してください。
- 実行中のSQLiteファイルを単純コピーせず、`LEDGER_DATABASE_PATH` の `-wal` / `-shm` を直接扱わないでください。
- ブラウザーのlocalStorageに以前登録したデータはサーバーへ自動移行されません。必要な記録は別途移行してください。
- この構成は単一サーバー向けです。複数サーバー構成や大規模な同時書き込みにはSQLiteを共有せず、PostgreSQL等へ移行してください。

## テスト

```powershell
.\.venv\Scripts\python -m unittest discover -s tests -p "test_*.py"
```

フロントエンドの画面操作・CSV回帰テストは次のコマンドで実行します。登録成功後の検索画面への遷移、登録失敗時に画面へ留まること、複数件登録時のCSV紐づけ、CSV付き詳細画面の表示を確認します。CSVなし・従来添付のみ・CSV読み込み中の描画テストも含みます。

```powershell
npm --prefix frontend test
```
